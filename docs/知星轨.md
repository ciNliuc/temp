# 知星轨 READ ME

（名字暂定为"知星轨" 知-知识 星-目标 轨-轨迹）

## 前言

一切一切的开始是 ds 移动端的限额政策。周围的人都在转向其它 ai 软件，kimi 也好，豆包也好，gpt 也好，甚至不再使用 ai：这是一个巨大的机会，我们可以用这一机会去填补这一需求。

但是一个免费的 ds 移动端不值得我们去开发，或者说这种投机行为本身也不长久，而是说我们终于可以借这个机会去顺便解决我们的痛点，我们大学生的；记不住哪天考试，ds 可以帮你记住，判断不了绩点够不够，ds 可以帮你计算，期末不知道怎么复习，ds 可以根据你的询问题目和错题来出模拟题。我们需要一个由 ds 驱动的新"muse"，一个人助理。

一切一切的开始来自于 ds 移动端限额政策，但是事情的发生已经开始于人们对于美好生活的需求。我们不止做一个替代品。

## 简言

知星轨是一款专为大学生设计的移动端 AI 个人助理，名字寓意"知有所向，行有轨迹"。它是由 ds 驱动，基本 agent 继承 dsh 框架，整合 dsh 常用的插件，帮助学生整理课程通知、管理作业与考试 DDL、制定复习计划，并协调学习、生活和成长目标等等大学生所痛点的需求。

它也可以允许用户去养成自己独有的 ai，它不止于助理，更是一个平等的伙伴。

## 正言

### 基本

现在"知星轨"有三个板块，第一个是 ds 移动端 session 板块，第二个是学生学习板块，第三个是养成系 ai 板块。

前者是主要界面，而第二板块是对于第一个总结精炼提取：这个提取有很高的标准，对于注意力漂移情况几乎不能允许（后面有详细表诉），第三板块养鱼，养成系选择，探索板块。

现阶段，我们工作主要分为三大：

1. 具体化常见痛点以及功能。
2. 统一第一二板块的 agent 开发。
3. 第三个就是云端养鱼的研究，这一块主要是探索如何保持记忆的新 agent 和更像人的聊天。

### 第一板块 "ds 移动端"

我们的基本原则是减法原则，不要那么多功能，不要那么多按钮，不要尝试去教用户，我们应该减轻功能，顺应用户习惯。

继承 ds 移动端的界面风格，提高其流畅度，拓宽对于模型选择的自由度，以及给予用户添加插件的选项。（这个插件早已集成在移动端上，只是没有激活）

不要添加这么多功能，而是先让用户主动添加"插件"，才会有对应的功能。

安全政策非常重要，但是现在无法回答。

### 第二板块 学生学习板块

agent 架构很重要，怎么选择有效信息给主 session，同时不破坏客观事实是一个很难得问题，我们成此为 agent 注意力问题。

关于前面提到的 agent 注意力要求，可以如此具体化：

- 提取结果必须能回溯到原始通知或对话
- 时间、地点、课程名称等关键信息单独高亮
- 首次写入日历前由用户确认
- 无法确定的信息标记为"待确认"，不能补猜
- 修改原始通知后，同步更新对应任务
- 模型回答与结构化任务分开存储

但更重要的是我们要明确痛点，总结有用的功能。现以下是我们暂时总结的痛点和功能对照：

| 痛点 | 功能 |
| --- | --- |
| 记不住考试和作业时间 | ds 记忆自动提醒联合日历 |

### 第三板块 养鱼板块

ai 火出圈是 chatgpt，但是现在 ai 普及的今天，ai 说话有很独特的 ai 味，它说话不像活生生的人。

我们需要寻找一个新的架构，让人们可以去养成一个 ai，它像一个真正的人去思考，去生活，去与玩家共情：

在用户明确知道其为 AI 的前提下，提供稳定的人格、连续的互动记忆和可调整的表达方式，形成长期、可信且不越界的陪伴体验。

现实需求的是很多人想要养鱼，但是云端部署麻烦。这一板块只是探索区域，所以我们也只能对于这个区域"希望"。

## 协同合作

开发和探索都需要我们去学习和探索，都需要我们去花时间学习、实践和研究。所以去整合和统一我们的力量是非常重要的。

协同主要是 superagent，目前阶段，各个成员（现 4 个）每人一个 superagent，参与一个板块。现阶段我们主要是寻找：收集痛点、具体问题、总结灵感、设计功能；所以我们需要大家去在生活中思考和记录。

每个人的 superagent 可以连接自己的 QQ 机器人，有什么想法可以先给它记录。

## 研发规范（简）

除了研发规范，其它板块 ai 不得擅自改变内容。

PR 请求必须有两个以上懂代码的人人工审核才能通过。

github 的 issues 是代码问题，QQ 上的问题是功能问题。

所有人都能畅所欲言。

## 阶段目标

- 初步完成第一板块，完成移动端基本框架的代码
- 设计并补充好初步"开发规范"
- 收集痛点、具体问题、总结灵感、设计功能

现阶段是探索阶段，做加法；到了寒假是整合阶段，做减法。
